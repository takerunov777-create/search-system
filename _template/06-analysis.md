# 06-analysis — 分析・スコアリング・市場分析・予測生成

## 役割
検証済みデータから意味を読み取り、競合スコアリング・市場分析・SWOT・予測を生成する。

## 参照パターン
- open_deep_research: 推論フェーズ分離（収集→検証→分析を独立したフェーズで実行）
- market-research スキル: TAM/SAM/SOM 推定・競合ランドスケープ

---

## 前提原則

- **根拠のない主張を書かない** — 全数値・評価は verified_facts.json の `confirmed` クレームに基づく
- **`unverified` は明示する** — 使用する場合は「未確認情報」と注記する
- **`conflicted` は両論を示す** — どちらか一方を採用しない
- **推論と事実を分ける** — 「データが示すこと」と「そこから推論されること」を区別する

---

## 実行手順

### Step 1: 入力を読み込む

- `data/{セッション}/verified/verified_facts.json`
- `data/{セッション}/verified/conflicts.json`
- `data/{セッション}/questions.json`
- `prompt.md`

### Step 2: 情報を圧縮・構造化する

verified_facts.json の `confirmed` クレームを以下のカテゴリに分類する:

- **企業プロファイル** — 各競合の基本情報（設立・本社・従業員・ビジネスモデル）
- **財務情報** — 売上・調達・利益・バリュエーション
- **製品情報** — 機能・価格・対応言語・統合サービス
- **市場情報** — シェア・成長率・顧客数・地域展開
- **最新動向** — 直近 12 ヶ月の主要ニュース・リリース

### Step 3: 競合スコアリング

各競合に対して 1〜5 点でスコアリングする（5 が最高）。

| 評価軸 | 定義 | 判断基準の例 |
|---|---|---|
| 製品力 | 機能・品質・差別化度 | 機能数、ユーザー評価、差別化要素 |
| 市場シェア | 推定占有率・成長速度 | シェア数値、顧客数成長率 |
| 資金力 | 調達額・財務健全性 | 累計調達額、最終ラウンド |
| ブランド | 認知度・評判 | メディア露出、NPS、レビュー評点 |
| 技術力 | 技術優位性・R&D | 特許数、エンジニア比率、技術記事 |
| 脅威度 | 自社への直接的な競合度 | 同一顧客層、同一機能、価格競合 |

**スコア付けのルール:**
- `confirmed` データのみに基づく
- データがない評価軸は `null`（0 にしない）
- スコアの根拠（使用した claim_id）を記録する

```json
{
  "competitor": "A社",
  "scores": {
    "製品力": { "score": 4, "basis": ["C021", "C034"], "note": "機能数業界最多" },
    "市場シェア": { "score": 3, "basis": ["C008"], "note": "国内推定28-40%（conflicted）" },
    "資金力": { "score": 5, "basis": ["C015"], "note": "累計300億円調達" },
    "ブランド": { "score": 4, "basis": ["C041", "C042"], "note": "" },
    "技術力": { "score": null, "basis": [], "note": "データ不足" },
    "脅威度": { "score": 4, "basis": ["C003"], "note": "同一顧客層・類似機能" }
  },
  "total": 20,
  "data_quality": "Medium"
}
```

### Step 4: 市場分析

**4-1. TAM / SAM / SOM 推定**

- `confirmed` の市場規模データを収集する
- 複数ソースがある場合は中央値を採用し、レンジを示す
- 推定根拠（ボトムアップ / トップダウン）を明記する

**4-2. 市場成長率**

- YoY 成長率を算出する（データがある年次のみ）
- CAGR を計算する（3 年以上のデータがある場合）

**4-3. 市場トレンドの特定**

verified_facts から以下を抽出する:
- 技術的変化（AI 活用・クラウド移行・モバイル化 等）
- 規制・法的変化
- 顧客行動の変化
- 新規参入・M&A の動向

### Step 5: SWOT 分析

`prompt.md` の調査主体（自社またはテーマ）に対して SWOT を生成する。

**ルール:**
- 各項目は `confirmed` クレームを根拠とする
- 各項目に claim_id を紐づける
- 根拠のない項目は記載しない

### Step 6: ポジショニング分析

全競合を 2 軸で配置するデータを生成する。

軸の例（テーマに応じて選択）:
- 価格（低〜高） × 機能（シンプル〜多機能）
- ターゲット（SMB〜Enterprise） × 市場（国内〜グローバル）
- 成長速度 × 市場シェア

各競合に x, y 座標値（1〜10）を付与する。

### Step 7: 予測生成（Phase 8 用）

verified_facts とトレンド分析に基づき、**3 つの予測** を生成する。

各予測のフォーマット:
```json
{
  "pred_id": "PRED_001",
  "session": "...",
  "created_at": "2026-03-25",
  "prediction": "A社は2026年9月末までに国内シェアを35%超に拡大する",
  "basis": ["C008", "C015", "C043"],
  "confidence": 65,
  "verification_date": "2026-09-30",
  "category": "市場シェア"
}
```

- `confidence`: 10〜90% の範囲（100% は認めない）
- `verification_date`: 6〜18 ヶ月後の具体的な日付
- 楽観・中立・悲観の 3 シナリオを混在させる

---

## 出力

```
data/{セッション}/analysis/
  competitor_scores.json   ← 競合スコアリング
  market.json              ← TAM/SAM/SOM・成長率・トレンド
  swot.json                ← SWOT 分析
  positioning.json         ← ポジショニングマップデータ
  predictions.json         ← 予測 3 件（Phase 8 に渡す）
```

完了後「分析完了: {N}社スコアリング / 予測{M}件生成」と表示する。

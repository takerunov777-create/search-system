# 00-orchestrator — 全体フロー制御

## 役割
競合調査の全フェーズを順序制御し、並列実行可能なタスクを並列化する。

---

## 実行前チェック

1. `prompt.md` が存在するか確認する
   - 存在しない場合 → `_template/00a-generate-prompt.md` を先に実行する
   - 存在する場合 → そのまま続行する

2. 出力ディレクトリを準備する
   ```
   data/YYYY-MM-DD_{テーマ名}/raw/
   data/YYYY-MM-DD_{テーマ名}/verified/
   data/YYYY-MM-DD_{テーマ名}/analysis/
   report/
   track-record/
   ```
   ※ `YYYY-MM-DD` は本日の日付。`{テーマ名}` は `prompt.md` の調査対象名（スペースをアンダースコアに変換）。

---

## 実行シーケンス

### Step 1: 要件明確化（直列）
`_template/01-clarify.md` を読み込み、指示に従って実行する。
完了後、出力 JSON を `data/{セッション}/clarify.json` に保存する。

### Step 2: ペルソナ生成（直列）
`_template/02-persona.md` を読み込み、指示に従って実行する。
完了後、統合サブ質問リストを `data/{セッション}/questions.json` に保存する。

### Step 3: 検索実行（並列）
`_template/03-search-strategy.md` を読み込み、各サブ質問を独立エージェントに割り当てる。

**並列実行ルール:**
- 各サブ質問は独立しているため、並列実行する
- Agent tool を使い、各エージェントに以下を渡す:
  - 対象サブ質問（Q番号・テキスト・言語）
  - 検索クエリ一覧（日本語・英語・バリエーション）
  - 出力先パス
- 最大 5 エージェントを同時起動する

### Step 4: データ収集（Step 3 と同時進行）
`_template/04-data-collection.md` を読み込み、検索結果が届き次第、構造化して保存する。

### Step 5: 検証（直列）
`_template/05-verification.md` を読み込み、収集データ全体に対して検証を実行する。

### Step 6: 分析（直列）
`_template/06-analysis.md` を読み込み、検証済みデータから分析を実行する。

### Step 7: レポート生成（直列）
`_template/07-report.md` を読み込み、分析結果から HTML レポートを生成する。

### Step 8: トラックレコード更新（直列）
`_template/08-track-record.md` を読み込み、分析で生成した予測を記録する。

---

## エラーハンドリング

| 状況 | 対応 |
|---|---|
| フェーズが失敗した場合 | エラー内容を表示し、そのフェーズを再試行する（最大 2 回） |
| 検索結果が 0 件の場合 | クエリを変更して再検索する（最大 3 バリエーション） |
| WebFetch がタイムアウトした場合 | そのURLをスキップし、`error_log.json` に記録する |
| 全フェーズ完了後 | 出力ファイル一覧と統計をサマリー表示する |

---

## 完了時の出力サマリー

全フェーズ完了後、以下を表示する:
- 収集ソース数・検証済み事実数・信頼度分布
- 生成した予測数
- レポートの出力パス
- 所要時間（フェーズ別）

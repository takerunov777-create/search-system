# 02-persona — ペルソナ駆動調査（STORM 方式）

## 役割
異なる立場の仮想専門家（3〜5 人）を定義し、各ペルソナの視点から追加質問を生成する。
調査の盲点を排除し、単一視点の偏りを防ぐ。

## 参照パターン
Stanford STORM の Perspective-Guided Question Asking:
「Wikipedia ライターと専門家の対話シミュレーション」から着想。
調査テーマの周辺記事・業界レポートを参照して視点の多様性を確保する。

---

## 実行手順

### Step 1: 入力を読み込む

- `prompt.md`（調査テーマ・目的・想定読者）
- `data/{セッション}/clarify.json`（フェーズ1のサブ質問リスト）

### Step 2: 適切なペルソナを選定する

調査テーマと想定読者に応じて、以下のリストから **3〜5 人** を選ぶ。
同じカテゴリのペルソナが重複しないようにする。

**ペルソナ候補プール:**

| ペルソナ | 関心軸 |
|---|---|
| 業界アナリスト | 市場規模・シェア・トレンド・将来予測 |
| 投資家（VC/PE） | 成長性・収益性・Exit・リスク |
| 製品マネージャー | 機能・UX・ロードマップ・差別化 |
| エンジニア・CTO | 技術スタック・スケーラビリティ・特許 |
| 営業・事業開発 | 顧客獲得コスト・チャネル・パートナー |
| エンドユーザー | 使いやすさ・価格・サポート・口コミ |
| マーケター | ブランド・ポジショニング・広告戦略 |
| 規制当局 | コンプライアンス・法規制・訴訟リスク |
| 既存顧客 | 継続利用理由・不満点・スイッチ意向 |
| 潜在競合 | 参入障壁・模倣可能性・差別化要素 |

### Step 3: 各ペルソナを定義する

```
### {名前}（{役職} / {組織タイプ}）

**背景:** {経験年数・専門領域・立場}
**最大の関心:** {このテーマで最も知りたいこと}
**思考の癖:** {楽観的/懐疑的/数字重視/定性重視 など}
```

### Step 4: ペルソナごとに追加質問を生成する（各 3〜5 問）

各ペルソナが「自分の立場から聞きたい質問」を生成する。
既存のサブ質問（clarify.json）とは異なる角度で問う。

**質問生成のルール:**
- 「なぜ？」「どの程度？」「誰が？」「いつから？」を意識する
- 反証・リスク・限界を問う質問を必ず 1 問含める
- 楽観的すぎる質問のみにならないようにする

### Step 5: 質問を統合・優先度付けする

1. 全ペルソナの質問と clarify.json の質問を合わせる
2. 意味が重複する質問を統合する（より具体的な方を残す）
3. 優先度を再評価する（ペルソナ数が多い質問 → 優先度 Up）
4. 最終的に **8〜15 問** に絞る

---

## 出力

`data/{セッション}/questions.json` に保存する:

```json
{
  "personas": [
    {
      "name": "...",
      "role": "...",
      "background": "...",
      "main_interest": "...",
      "questions": [
        { "id": "P1Q1", "text": "...", "priority": "High" }
      ]
    }
  ],
  "integrated_questions": [
    {
      "id": "Q01",
      "text": "...",
      "priority": "High",
      "source_personas": ["P1", "P3"],
      "category": "市場シェア",
      "languages": ["ja", "en"],
      "source_types": ["news", "database"]
    }
  ]
}
```

完了後「ペルソナ生成完了: {N}人のペルソナから{M}問の統合サブ質問を生成しました」と表示する。
